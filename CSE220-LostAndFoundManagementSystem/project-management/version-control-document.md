## 1. Purpose

This document tracks the evolution of major project artifacts so the team can identify the current version, author, reviewer, repository location, and change description. GitHub commit history and Pull Requests provide the detailed audit trail for each revision.

## 2. Version Numbering Convention

- **V-1.0** - first published version
- **V-1.1** - minor revision or correction without a major redesign
- **V-2.0** - major revision with significant changes

Older versions must remain in their version folders. Do not overwrite an approved historical version.

## 6. GitHub Change Procedure

1. Start from the latest `main` branch.
2. Work on the student's personal branch.
3. Copy the current approved artifact into a new version folder when the artifact version changes.
4. Update the artifact header and change description.
5. Update this Version Control Document.
6. Commit using a traceable ID such as `[FR-01]`, `[TC-001]`, `[US-07]`, or `[BUG-001]`.
7. Push the personal branch.
8. Create a Pull Request to `main`.
9. Have another team member review the PR.
10. Merge the PR and add the PR/commit reference to the change log.
